# 《别吵醒奶龙》AI 协作规范

| 项 | 内容 |
| --- | --- |
| 版本 | v1.0 |
| 配套规则 | `.cursor/rules/ai-collaboration.mdc`（alwaysApply） |
| Skill | `frontend-design`、`design-taste-frontend` |

本规范约定：**人怎么下单、AI 怎么执行、何时读哪份 Skill、如何验收与提交**。

---

## 1. 角色分工

| 角色 | 负责 |
| --- | --- |
| 人（导演） | 定目标、选场景/IP 策略、验收手感与惊吓是否「好笑」、是否公开上线 |
| AI（执行） | 按需求/模块设计/技术选型实现；打磨参数；写文档与 commit |
| Skill | 提供设计判断与检查流程，不替代玩法状态机 |

---

## 2. 下单方式（推荐话术）

一次任务尽量包含：

1. **目标**：例如「M0 灰盒跑通 SLEEP→WARN→CATCH」
2. **范围**：改哪些模块 / 不要动哪些
3. **验收**：可操作的检查句（「预警出现后 180ms 内松手不死」）
4. **约束**：IP 用原创或奶龙、要不要音效、是否允许大改目录

示例：

> 按功能模块设计实现 M0：Vite+TS 灰盒，色块奶龙，无精美图。验收：按住加分、预警松手存活、峰内按住跳 CATCH。完成后 commit。

避免：只说「做好看一点」而不说改壳还是改玩法。

---

## 3. AI 执行协议（强制）

### 3.1 开工前阅读顺序

1. 用户本轮指令  
2. `docs/功能模块设计-别吵醒奶龙.md`（改架构时）  
3. `docs/技术选型.md` / `docs/代码规范.md`  
4. 按任务类型启用 Skill（见下表）

### 3.2 Skill 启用表

| 任务类型 | 读取 |
| --- | --- |
| 玩法 / 状态机 / 音频判定 / Canvas 循环 | **不跑** Taste 全流程；遵守模块设计与代码规范 |
| HUD、标题、结算、按钮、配色字体 | **先读** `frontend-design`；先出 token 再写 CSS |
| 宣传落地页、作品集页、对外营销页 | **完整** `design-taste-frontend` run（draw → 构建 → inspect） |
| 用户抱怨「太 AI / 太模板」 | frontend-design；若是整页营销再上 Taste |

### 3.3 实现中

- 小步交付：可运行 > 完美美术  
- 不擅自引入 React/Phaser/Tailwind（与选型冲突须先征得同意）  
- 不擅自扩大范围（不做排行榜、账号、广告）  
- 手感只调 `config`；改判定逻辑要在回复里说明  
- 交付结束：**git commit**（见 git 规则）；默认不 push  

### 3.4 回复格式（对人）

- 开头 1–2 句说清结果  
- 需要时列：改了什么、怎么玩/怎么验、风险（IP 等）  
- 不贴大段无关代码；关键路径可引用文件  

---

## 4. 视觉协作细则

对齐 `frontend-design`：

1. 先声明题材锚点（熟睡、冰箱、惊吓反差）  
2. 给出 4–6 色 + 字体角色 + 一句原则  
3. 自检是否落入紫渐变 / 三卡片 / 奶油陶土等默认套餐  
4. 有截图能力时，改壳后看手机宽截图再收工  

Taste 额外：

- 仅营销页走 `scripts/draw.mjs` / `inspect.mjs`  
- 产物目录 `.taste-skill/` 不强制提交；有价值的方向选择可记入 docs  

---

## 5. 里程碑协作节奏

| 阶段 | 人验收焦点 | AI 交付物 |
| --- | --- | --- |
| M0 | 规则是否成立 | 可玩灰盒 + commit |
| M1 | 预警可读、惊吓够爽 | 表情档位 + 音效 |
| M2 | 零文案、手机可玩 | HUD/结算/静音/存储 |
| M3 | 是否值得发链接 | 皮肤/分享/难度 |

每阶段结束：人只需回「过 / 改某某参数 / 重做壳」，避免同时改玩法+换栈。

---

## 6. 冲突优先级

从高到低：

1. 用户当句明确指令（含「先别提交」）  
2. 本仓库 `.cursor/rules/*`（git、代码、协作）  
3. `docs/*` 需求与设计  
4. `frontend-design` / Taste Skill  
5. 模型默认审美与习惯  

---

## 7. 禁止事项（AI）

- 未授权使用官方奶龙素材商用打包  
- 用 Skill 流程替换核心玩法架构  
- 为「好看」引入重框架导致首屏变慢  
- 提交密钥或乱改 git config  
- 隐瞒破坏性操作（删档、force push）  

---

## 8. 人侧检查清单（每轮可选）

- [ ] 指令是否有验收句  
- [ ] AI 是否误用了 Taste 全流程做 Canvas  
- [ ] 是否跑得起来、手机上能否按住  
- [ ] 是否已 commit  
- [ ] IP / 素材是否仍合规
