## 1. 背景与机会

### 1.1 产品一句话

玩家趁**睡着的奶龙**没有察觉时，偷偷完成一件「危险小事」；一旦被奶龙发现，触发夸张 jump scare，本局结束。

### 1.2 为什么值得做

| 依据 | 说明 |
| --- | --- |
| 已验证玩法 | 刷猫类「偷偷做某事 → 微表情预警 → 被抓惊吓」在短视频平台被证明可传播 |
| 低认知成本 | 规则可凭画面理解，无需教程文案 |
| 奶龙素材势能 | 黄色圆润外形、夸张表情、魔性反应，天然适合 reaction / 录屏二创 |
| 网页优势 | 点开即玩、跨端一致、评论区可丢链接，利于传播闭环 |
| vibecoding 友好 | 单场景、单循环、状态机清晰，适合快速出可玩原型 |

### 1.3 非目标（本期不做）

- 不做复杂养成、关卡树、商城、账号体系
- 不做联机对战、排行榜服务端（MVP 可仅本地最高分）
- 不做完整剧情叙事
- 不追求 3D 高精美术，优先可读表情与惊吓节奏

## 2. 问题定义与成功标准

### 2.1 要验证的核心假设

1. **4 秒张力环成立**：任意一次「行动 → 预警 → 收手/继续 → 结果」应在约 3–6 秒内完成一个可理解的情绪弧。
2. **零文案可上手**：无说明文字时，≥80% 试玩者能在 10 秒内开始正确操作。
3. **失败值得录**：被抓画面 + 音效足以让人想截屏/录屏分享。

### 2.2 成功指标（MVP）

| 指标 | 目标（定性验收） |
| --- | --- |
| 首次理解时间 | 打开页面后 10 秒内完成第一次有效操作 |
| 单局时长 | 多数局 5–40 秒；高分局长局可超过 1 分钟 |
| 再玩意愿 | 失败后「再来一次」点击率主观预期高（按钮极近、无阻拦） |
| 可分享时刻 | 被抓瞬间具备：表情突变 + 音效刺点 + 分数定格 |
| 技术体验 | 手机浏览器可玩；首屏可交互尽量 < 3 秒 |

## 3. 用户与使用场景

### 3.1 目标用户

| 画像 | 动机 | 场景 |
| --- | --- | --- |
| 碎片时间玩家 | 杀时间、图一乐 | 通勤、摸鱼、等人 |
| 短视频创作者 | 找可录反应素材 | 录 facecam / 双人惊吓 |
| 梗图受众 | 玩「奶龙」相关抽象幽默 | 微信/抖音评论区点链接就玩 |

### 3.2 关键用户故事

1. 作为玩家，我希望**不用看规则**就能知道：要偷偷做事，被发现就完。
2. 作为玩家，我希望在奶龙快醒时有**清晰预警**，让我决定松手或赌一把。
3. 作为玩家，我希望被抓时**足够夸张好笑**，失败也不难受。
4. 作为创作者，我希望游戏在手机上也好录，惊吓时机稳定、可剪辑。

## 4. 产品定位与差异化

### 4.1 对标拆解（Brush Nooli 公式）

| 公式要素 | 刷猫原版 | 《别吵醒奶龙》映射 |
| --- | --- | --- |
| 禁止行为 | 趁睡着刷毛 | 趁睡着偷偷做事（见场景） |
| 安全窗口 | 眼睛闭合 | 奶龙熟睡态（闭眼/打呼噜） |
| 预警信号 | 耳动、尾动、半睁眼 | 肚子起伏乱、眼睛眯缝、尾巴/角微动、哼声变调 |
| 失败惩罚 | Jump scare + 分数清零/结束 | 奶龙暴起惊吓 + 「我是奶龙！」式反应 + 本局结束 |
| 正反馈 | 分数累加 | 分数/进度条/偷到的物品计数 |
| 传播载体 | 4 秒张力 + 死亡屏 | 同结构，换奶龙表情包级反应 |

### 4.2 差异点（避免纯换皮无记忆点）

- **角色反应更魔性**：失败不只是「生气」，而是奶龙式夸张（瞪眼、张嘴、扑脸、口头禅式音效）。
- **行为可多场景轮换**：同一套状态机，可切换「关闹钟 / 偷冰箱 / 改 PPT」皮肤，增强二创与更新空间。
- **预警链路更「身体语言」**：按「呼吸 → 肢体 → 眼睛」递进，贴近真实「别吵醒」直觉。

## 5. 核心玩法需求

### 5.1 核心循环（必须实现）

```
进入睡眠态
  → 玩家按住/滑动「偷偷行动」
  → 分数/进度上涨（仅在安全或半危险窗口）
  → 随机进入预警态（微表情升级）
  → 玩家松手停下 / 或继续赌
  → 若在危险峰值仍行动 → 被抓（Jump Scare）→ 结算 → 再来一局
  → 若及时松手 → 奶龙重新入睡 → 循环
```

### 5.2 4 秒张力环（设计约束，非可选）

单次可录片段建议节拍（可调参，但结构固定）：

| 节拍 | 时长建议 | 画面 | 玩家动作 |
| --- | --- | --- | --- |
| Setup | 0.0–1.0s | 奶龙熟睡，环境安静 | 开始行动 |
| Tension | 1.0–3.0s | 分数上涨，偶发轻微异动 | 持续行动 |
| Trigger | 3.0–3.5s | 明确预警（眯眼/哼声/肚子一抖） | 应松手 |
| Payoff | 3.5–4.5s | 被抓惊吓或惊险躲过 | 失败或续命 |

> 验收：任意高光失败录像剪到 5–8 秒仍能看懂整段故事。

### 5.3 游戏状态机（功能需求）

| 状态 ID | 名称 | 进入条件 | 玩家可行动？ | 输出 |
| --- | --- | --- | --- | --- |
| `BOOT` | 启动/标题 | 打开页面 | 点开始 | 进入 `SLEEP` |
| `SLEEP` | 熟睡安全 | 开局或预警解除 | 是，加分 | 随机转 `WARN` |
| `WARN` | 微表情预警 | 定时/概率触发 | 是，但高风险 | 松手→回 `SLEEP`；继续→可能 `CATCH` |
| `CATCH` | 被抓惊吓 | 预警高峰仍在行动，或判定失败 | 否 | 播动画 → `RESULT` |
| `RESULT` | 结算 | 惊吓结束 | 再来一次 / 分享 | 回 `SLEEP` 或标题 |
| `PAUSE` | 暂停（可选） | 切后台/按暂停 | 否 | 恢复原状态 |

### 5.4 判定规则（必须可调参）

| 参数 | 说明 | MVP 建议 |
| --- | --- | --- |
| `safeHoldScoreRate` | 安全态每秒得分 | 可感知上涨 |
| `warnDuration` | 单次预警持续 | 0.6–1.5s 可随难度变短 |
| `catchGraceMs` | 预警出现后的反应宽限 | 120–250ms，避免「完全来不及」的恶心感 |
| `warnIntensityCurve` | 预警强度曲线 | 轻→中→危，危峰才必抓 |
| `spawnWarnInterval` | 两次预警间隔 | 随分数缩短，制造高压 |
| `missPenalty` | 是否允许「空按」 | MVP：未按住不得分即可 |

**失败条件（MVP）**

- 在 `WARN` 的危险峰值窗口内，玩家仍处于「行动中」→ `CATCH`
- （可选进阶）连续忽略轻预警 N 次 → 强制暴起

**成功/持续条件**

- 无通关必要条件；以**生存时长 / 累计分数 / 偷取进度**为成就
- MVP 以「刷新本地最高分」为唯一长期目标

## 6. 场景与内容需求

### 6.1 MVP 主场景（三选一落地，其余作皮肤扩展）

优先推荐 **场景 A**（最贴「别吵醒」与奶龙吃货人设）。

#### 场景 A：偷吃冰箱（推荐 MVP）

| 项 | 内容 |
| --- | --- |
| 玩家行为 | 按住打开冰箱门 / 往外抽食物 |
| 正反馈 | 食物一件件溜走，分数 + 堆叠展示 |
| 奶龙睡眠表现 | 靠着或趴着打呼，大肚子起伏 |
| 预警 | 鼻子动、流口水、眼睛眯一条缝、「哼」 |
| 被抓 | 奶龙弹起抢食 / 脸冲镜头大叫 |

#### 场景 B：偷偷关闹钟

| 项 | 内容 |
| --- | --- |
| 玩家行为 | 按住去按掉狂响的闹钟 |
| 张力来源 | 闹钟声本身制造焦虑 |
| 被抓 | 奶龙被闹醒暴起 |

#### 场景 C：偷偷改老板 PPT（更偏职场梗）

| 项 | 内容 |
| --- | --- |
| 玩家行为 | 按住在键盘上改字 |
| 风险 | 更抽象，零文案稍弱，作第二弹皮肤更合适 |

### 6.2 角色表现需求（奶龙）

基于公开人设与梗传播特征，表现应强调：

- **视觉识别**：黄皮肤、圆脑袋、duang 肚子、大眼睛（简化 Q 版即可）
- **睡眠态**：可爱、无害、可被低估
- **预警态**：从萌到危险的过渡可读（眯眼 > 皱眉 > 睁眼一瞬）
- **惊吓态**：夸张、短、响；可融入口头禅式音效（注意版权，见风险）

表情阶段建议最少 4 档：

1. Deep Sleep  
2. Light Stir（轻动）  
3. Almost Awake（危险）  
4. Caught（惊吓定格/短动画）

### 6.3 音频需求

| 类型 | 需求 |
| --- | --- |
| BGM | 可无，或极轻环境声；避免盖过预警 |
| 睡眠 SFX | 呼噜、轻微鼻息（循环） |
| 预警 SFX | 短促哼声 / 布料动 / 冰箱门缝音 |
| Catch SFX | 强烈刺点（惊吓音 + 角色吼） |
| UI SFX | 开始、再来一次轻反馈 |
| 合规 | MVP 使用原创或可商用素材；勿直接抽取官方动画音效 |

## 7. 交互与界面需求

### 7.1 零文案门槛（硬性）

- 首屏可用**演示动画**或**手势光标**代替文字教程
- 主操作：**按住 = 行动，松开 = 停下**（触屏与鼠标一致）
- 若必须有字，仅保留：标题、分数、按钮「再来一次」
- 不出现超过两句的规则说明页（MVP）

### 7.2 界面信息架构（极简）

| 元素 | 是否 MVP 必须 | 说明 |
| --- | --- | --- |
| 标题《别吵醒奶龙》 | 是 | 品牌识别 |
| 当前分数 | 是 | 即时反馈 |
| 历史最高分 | 是 | 本地存储 |
| 主操作热区 | 是 | 大按钮/按住区域，移动端友好 |
| 再来一次 | 是 | 结算页最大按钮 |
| 静音开关 | 是 | 惊吓音可控 |
| 分享按钮 | 可选 | Web Share API / 复制文案 |
| 设置/难度 | 可选 | 后期 |

### 7.3 平台与操作

| 平台 | 要求 |
| --- | --- |
| 手机浏览器 | 主目标；竖屏优先或自适应 |
| 桌面浏览器 | 鼠标按住等价触控 |
| 操作冲突 | 避免页面滚动抢手势；`touch-action: none` 于画布区 |
| 无障碍（基础） | 静音；不要仅靠颜色区分预警（加动效/声音） |

## 8. 功能需求清单

### 8.1 Must（MVP）

1. 单页打开即玩，无账号、无下载  
2. 睡眠 / 预警 / 被抓 / 结算 状态机完整可玩  
3. 按住行动、松开停止  
4. 分数累计 + 本地最高分  
5. Jump scare 动画 + 音效  
6. 一键再来  
7. 静音  
8. 移动端可玩布局  

### 8.2 Should（第一迭代）

1. 难度随分数爬升（预警更频、窗口更短）  
2. 至少 1 套完整场景美术（偷冰箱）  
3. 轻微屏幕震动（支持时）  
4. 「差点被抓」反馈（松手成功的心跳感）  
5. 结算页展示本次分数与最高分对比  

### 8.3 Could（后续）

1. 多场景皮肤切换（闹钟 / PPT）  
2. 每日种子随机预警节奏  
3. 可分享成绩图（Canvas 导出）  
4. 轻松/地狱难度  
5. 无惊吓模式（仅结束动画，适合敏感用户）  
6. 简单成就（生存 30s、满分逃过 10 次预警等）  

### 8.4 Won't（明确不做）

1. 付费复活、强制广告（个人 vibe 版）  
2. 复杂剧情与对话树  
3. UGC 关卡编辑  
4. 未经授权的官方资源直接商用打包

## 9. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 常设备 60fps 目标；低端机可降至 30fps 仍可读 |
| 体积 | 首包尽量小；图集/音效压缩；可接受纯程序图形 MVP |
| 兼容 | 近两年 Chrome / Safari / 微信内置浏览器 |
| 可靠性 | 切后台暂停逻辑，避免「切回来秒死」不公平 |
| 隐私 | 仅 `localStorage` 存最高分；无强制采集 |
| 可调参 | 预警节奏、宽限、得分速率集中配置，便于手感打磨 |

## 10. 技术需求（建议）

| 项 | 建议 |

## 11. 内容与合规风险（必须纳入需求）

### 11.1 IP 风险

「奶龙 / Nailoong」为深圳第七印象等主体相关的商业 IP。  

**需求约束：**

- **个人学习 / 非公开 demo**：可用「致敬风格」的原创黄龙形象，命名可标注 fan-made / 练习作。  
- **公开上线 / 带流量分发**：需获得授权，或改为**原创角色**（保留玩法，不使用奶龙名称、官方造型与音效）。  
- 文档中的「奶龙」指玩法设定对象；实施前需在立项中二选一：`授权使用` / `原创替换角色`。

### 11.2 内容分级

- Jump scare 保持「夸张搞笑」，避免血腥恐怖  
- 提供静音；可选「减少惊吓」  
- 文案避免低俗与侵权台词直接照搬官方

### 11.3 传播伦理

- 面向梗受众时可偏抽象幽默，但避免引导针对儿童向 IP 的恶意引战作为产品卖点

## 12. 体验验收标准（Test Cases）

| 编号 | 用例 | 期望 |
| --- | --- | --- |
| T1 | 无教程进入，10 秒内是否开始按住 | 是 |
| T2 | 安全态按住 | 分数稳定增加 |
| T3 | 预警出现后立即松开 | 回到睡眠，不死亡 |
| T4 | 预警高峰仍按住 | 必进惊吓 |
| T5 | 惊吓期间再点击 | 不重复叠加逻辑错误 |
| T6 | 结算点再来一次 | 秒开新局，分数重置，最高分保留 |
| T7 | 静音后再被抓 | 无惊吓声，动画仍在 |
| T8 | 手机竖屏单手操作 | 热区可达，无误触滚动 |
| T9 | 首次点击前 | 音频策略不报错；手势后可播 |
| T10 | 录一段失败视频 6 秒 | 外人能看懂「偷→差点→被抓」 |

## 14. 开放问题（待决策）

1. 角色最终用 **奶龙授权形象** 还是 **原创黄龙**？  
2. MVP 场景确认是否锁定「偷冰箱」？  
3. 失败后分数是「本局结束保留展示」还是「清零只留最高分」？（建议：本局分展示 + 最高分更新）  
4. 是否需要「无惊吓」模式进入 MVP？  
5. 目标分发渠道：仅本地打开 / GitHub Pages / 国内网页宿主？是否影响合规与素材策略？

## 15. 结论与下一步

**需求结论：**  
本产品是一款以「别吵醒熟睡角色」为唯一核心的网页反应向小游戏。优先级不是内容体量，而是把 **预警可读性、松手博弈、惊吓爽感、再来一次摩擦为零** 打磨到可录、可传、可复玩。

**建议下一步：**
